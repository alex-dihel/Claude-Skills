Definition

A clickable UI element that triggers an action or submits a form when activated.

When to Use

  • Use primary type for the main call-to-action in a view or section
  • Use outline type for secondary actions alongside a primary button
  • Use transparent type for tertiary or low-emphasis actions

When Not to Use

  • Navigating between pages — use a Link instead
  • Toggling a setting on/off — use a Switch or Checkbox instead

Usage Rules

Do

  • Use one primary-type button per view/section to establish clear hierarchy
  • Keep labels short and action-oriented, verb-first (e.g. "Submit", "Continue")
  • Use the disabled status only when the action is genuinely unavailable, not as a substitute for validation messaging

Don't

  • Don't stack multiple primary-type buttons together
  • Don't use a button when a link is more appropriate (i.e. simple navigation)
  • Don't rely on color alone to convey the disabled status

Accessibility Notes

Unverified — design intent only

Keyboard: Focusable via Tab, activated with Enter/Space.

Screen reader: Disabled buttons are removed from the tab order and announced as disabled. Icon-only or icon+label buttons expose an accessible name via the label text; if icon-only, requires an explicit aria-label.

Other: Focus state is shown via a visible focus ring (matches the "focus" status variant). Color contrast for text/icon against each button surface should meet WCAG AA.
